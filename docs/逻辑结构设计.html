4.1 转换为关系数据模型

按照 E-R 图向关系模型转换的规则：①每一个实体转换为一个关系模式，实体的属性即关系的属性，实体的码即关系的码；②对于 1:n 的联系，将"1"端的主码并入"n"端关系作为外码，联系自身的属性一并并入；③对于 m:n 的联系，需单独转换为一个关系模式，其码为两端实体码的组合，联系的属性作为该关系的非主属性。据此，将图3-5 所示的系统总体 E-R 图转换为如下 7 个关系模式（实下划线表示主码，虚下划线表示外码）：

部门（部门编号，部门名称，办公地点，联系电话）
订阅人员（人员编号，姓名，性别，联系电话，通信地址，所属部门，用户名，口令，角色）
报刊类别（类别编号，类别名称，类别说明）
报刊（报刊编号，报刊名称，所属类别，刊期，单价，出版社，维护人）
订阅单（订单编号，订阅日期，起订日期，截止日期，总金额，订单状态，下单人，审核人，审核时间，审核意见）
订阅明细（订单编号，报刊编号，份数，订阅期数，小计金额）
操作日志（日志编号，操作人员，操作类型，操作内容，操作时间）

各联系的具体转换策略如表4-1 所示。其中"包含"联系为 m:n 联系，转换为独立的关系模式"订阅明细"；其余 6 个 1:n 联系均按规则并入"n"端关系。此外，"审核"联系除审核人外还带有审核时间、审核意见两个属性，一并并入订阅单关系。

4.2 关系模式的优化

4.2.1 函数依赖集与范式判定

对 4.1 节得到的各关系模式逐一写出函数依赖集，并依据函数依赖判定其达到的范式。判定结果汇总如表4-2 所示。

以订阅明细关系为例作典型分析：其主码为组合码（订单编号，报刊编号），非主属性份数、订阅期数、小计金额均完全函数依赖于整个主码，既不存在非主属性对码的部分依赖，也不存在非主属性之间的传递依赖（小计金额直接依赖于码，报刊单价并不在该关系中存储）；因此该关系达到 BCNF。订阅人员关系存在两个候选码（人员编号、用户名），所有非平凡函数依赖的决定因素（人员编号、用户名）均为候选码，满足 BCNF 的定义"每个非平凡依赖的决定因素必包含码"。

4.2.2 优化过程

在 E-R 图向关系模型转换及规范化过程中，主要进行了以下三项优化：

（1）合并 1:1 联系。初步设计时曾将"登录账号"（用户名、口令）作为独立实体与订阅人员建立 1:1 联系。由于账号与人员一一对应，拆开将导致每次登录验证都需要额外的连接操作，故按合并原则将账号属性并入订阅人员关系，"用户名"作为该关系的第二个候选码。

（2）m:n 联系独立成关系。订阅单与报刊之间的"包含"联系为 m:n，若直接在订阅单中存放多种报刊将违反第一范式，故独立转换为订阅明细关系，并以（订单编号，报刊编号）为组合码。

（3）消除传递依赖。初步设计中报刊关系曾冗余存储"类别名称"，存在传递依赖：报刊编号 → 类别编号 → 类别名称，类别更名时需修改所有该类报刊记录，产生更新异常。优化后仅保留外码"所属类别"，类别名称由报刊类别关系提供。同理，订阅单中只保存下单人编号而不冗余其部门信息。

需要说明的是，订阅明细中的小计金额与订阅单中的总金额属于派生属性（小计 = 单价 × 份数 × 订阅期数，总金额 = 各小计之和），理论上可由连接查询随时导出；工程上保留它们是为了报表统计性能与对账快照的需要，其一致性由数据库触发器自动维护（见 5.3.4 节），不影响范式判定。

4.3 视图设计

按照系统的访问控制需求和数据访问特点设计视图：查询模块的高频多表连接定义为视图以简化操作（简单性）；对敏感字段的屏蔽与"只看本人数据"的限制通过视图实现（安全性）；视图隔离了基本表结构变化对应用的影响（逻辑数据独立性）。共设计 7 个视图，一览如表4-3 所示，定义 SQL 如后。

表4-3 视图设计一览表
视图名称对应需求主要作用
v_user_brief查询模块展示人员公开信息安全性：屏蔽用户名、口令
v_order_detail按人员/报刊/部门查询订阅信息简单性：封装 5 表连接
v_pending_orders管理员审核工作台安全性：仅暴露待审核数据
v_person_stat按人员统计订阅量与金额简单性：封装分组统计
v_dept_stat按部门统计订阅量与金额简单性：封装分组统计
v_pub_stat按报刊统计订阅量与金额简单性：封装分组统计
v_user_orders订阅用户查看本人订单安全性：按登录账号的行级过滤
-- 视图1：订阅人员公开信息（屏蔽用户名与口令） CREATE OR REPLACE VIEW v_user_brief AS SELECT s.sub_id, s.sub_name, s.gender, s.phone, s.address, d.dept_name, s.role FROM subscriber s JOIN department d ON d.dept_id = s.dept_id; -- 视图2：订阅单明细全景（订单+下单人+部门+报刊+明细） CREATE OR REPLACE VIEW v_order_detail AS SELECT o.order_id, o.sub_date, o.start_date, o.end_date, o.order_status, o.total_amount, s.sub_id, s.sub_name, d.dept_name, p.pub_id, p.pub_name, det.quantity, det.periods, det.subtotal FROM subscription o JOIN subscriber s ON s.sub_id = o.orderer_id JOIN department d ON d.dept_id = s.dept_id JOIN subscription_detail det ON det.order_id = o.order_id JOIN publication p ON p.pub_id = det.pub_id; -- 视图3：待审核订阅单（审核工作台） CREATE OR REPLACE VIEW v_pending_orders AS SELECT o.order_id, s.sub_name, d.dept_name, o.sub_date, o.start_date, o.end_date, o.total_amount FROM subscription o JOIN subscriber s ON s.sub_id = o.orderer_id JOIN department d ON d.dept_id = s.dept_id WHERE o.order_status = '待审核';
-- 视图4：按人员订阅统计（仅统计已通过订单） CREATE OR REPLACE VIEW v_person_stat AS SELECT s.sub_id, s.sub_name, d.dept_name, COUNT(DISTINCT o.order_id) AS order_cnt, SUM(det.quantity) AS total_qty, SUM(det.subtotal) AS total_amount FROM subscription o JOIN subscriber s ON s.sub_id = o.orderer_id JOIN department d ON d.dept_id = s.dept_id JOIN subscription_detail det ON det.order_id = o.order_id WHERE o.order_status = '已通过' GROUP BY s.sub_id, s.sub_name, d.dept_name; -- 视图5：按部门订阅统计 CREATE OR REPLACE VIEW v_dept_stat AS SELECT d.dept_id, d.dept_name, COUNT(DISTINCT o.order_id) AS order_cnt, COUNT(DISTINCT s.sub_id) AS person_cnt, SUM(det.quantity) AS total_qty, SUM(det.subtotal) AS total_amount FROM subscription o JOIN subscriber s ON s.sub_id = o.orderer_id JOIN department d ON d.dept_id = s.dept_id JOIN subscription_detail det ON det.order_id = o.order_id WHERE o.order_status = '已通过' GROUP BY d.dept_id, d.dept_name; -- 视图6：按报刊订阅统计 CREATE OR REPLACE VIEW v_pub_stat AS SELECT p.pub_id, p.pub_name, c.cat_name, p.period, p.unit_price, SUM(det.quantity) AS total_qty, SUM(det.subtotal) AS total_amount FROM subscription_detail det JOIN publication p ON p.pub_id = det.pub_id JOIN category c ON c.cat_id = p.cat_id JOIN subscription o ON o.order_id = det.order_id WHERE o.order_status = '已通过' GROUP BY p.pub_id, p.pub_name, c.cat_name, p.period, p.unit_price;
-- 视图7：个人订单视图（行级安全：按数据库登录账号自动过滤， -- 账号名与订阅人员用户名一致时，仅返回本人订单） CREATE OR REPLACE VIEW v_user_orders AS SELECT o.order_id, o.sub_date, o.start_date, o.end_date, o.total_amount, o.order_status, p.pub_name, det.quantity, det.periods, det.subtotal FROM subscription o JOIN subscription_detail det ON det.order_id = o.order_id JOIN publication p ON p.pub_id = det.pub_id WHERE o.orderer_id = ( SELECT s.sub_id FROM subscriber s WHERE s.username = SUBSTRING_INDEX(CURRENT_USER(), '@', 1) );
