报刊订阅管理系统 · 需求分析

《数据库原理实践》课程设计报告 第二章（需求分析）初稿 ｜ 生成日期：2026-10-11 ｜ 模块划分与第三章 E-R 图保持一致

2.1 功能需求与系统功能模块图

通过对某企业报刊订阅业务的调研与分析，报刊订阅管理系统面向系统管理员、部门管理员、订阅用户三类角色，实现报刊订阅业务的全流程信息化管理。系统的功能需求如下：

（1）录入功能：系统管理员可录入部门信息、订阅人员信息、报刊类别与报刊基本信息，并为订阅人员分配登录账号与系统角色；（2）订阅功能：订阅用户（或由部门管理员代订）选定报刊、份数与订阅期限后生成订阅单，系统按“单价×份数×订阅期数”自动计算订阅金额，订阅单提交后由系统管理员审核生效；（3）查询功能：按人员、报刊、部门三个维度查询订阅信息，姓名与报刊名称支持模糊查询，查询结果可预览和打印；（4）统计功能：按报刊、人员、部门统计订阅数量与订阅金额，统计结果可预览和打印；（5）系统维护：包括订阅单审核、操作日志管理、数据备份与恢复、参数设置与权限管理等。

据此将系统自顶向下划分为系统管理、部门与人员管理、报刊信息管理、订阅管理、查询统计、系统维护六个功能模块，如图2-1 所示。其中系统管理模块负责身份验证与角色权限控制；部门与人员管理模块维护组织机构与人员档案并分配账号；报刊信息管理模块维护报刊类别与报刊基础数据；订阅管理模块是核心业务模块，完成订阅登记、金额计算与订阅单生成；查询统计模块提供三维度的查询、统计与打印输出；系统维护模块承担订阅单审核、日志管理与数据备份。该模块划分与第三章概念结构设计中的分 E-R 图划分保持一致。

2.2 系统数据流图

数据流图采用自顶向下的方法绘制：先给出反映系统与外部实体关系的顶层图，再分解得到 0 层图，最后对核心加工 P4 给出 1 层图。图中方框表示外部实体，圆圈表示加工，双横线表示数据存储，带名称的箭头表示数据流。

2.2.1 顶层数据流图

顶层图把整个系统抽象为一个加工 P0。系统与三类外部实体交换数据：订阅用户向系统提交订阅申请与查询统计请求，系统返回订阅单（含金额）与查询统计结果；部门管理员可代本部门人员办理订阅并进行查询统计；系统管理员负责录入部门、人员、报刊等基础数据，并对订阅单进行审核与系统维护。

2.2.2 0 层数据流图

将顶层图按功能分解为 P1 系统管理、P2 部门与人员管理、P3 报刊信息管理、P4 订阅管理、P5 查询统计、P6 系统维护六个加工，对应图2-1 中的六个功能模块。P4 订阅管理是核心加工：读取 D4 报刊中的单价，将生成的订阅单及明细写入 D5，并写操作日志；P6 系统维护读取待审核订阅单、将审核状态写回 D5；P5 查询统计为只读加工，从 D1、D4、D5 等存储读取数据。为保持图面清晰，各加工写入 D6 操作日志的流程仅画出 P4、P6 两条，其余加工写日志从略；P5 对 D2、D3 的读取也从略。除 P4、P6 外，父图与子图的输入输出数据流保持平衡。

2.2.3 订阅管理加工的 1 层数据流图

对核心加工 P4 进一步分解为四个子加工：P4.1 接收订阅申请并校验有效性，P4.2 从 D4 检索单价，P4.3 按“单价×份数×订阅期数”计算小计金额并汇总总金额，P4.4 生成订阅单与订阅明细写入 D5 并记录日志，最后向用户返回订阅单确认。部门管理员代订走同一流程，仅申请人字段不同。1 层图与父图 P4 的输入输出数据流一致，满足父子图平衡。

2.3.5 处理过程

编号名称加工逻辑主要输入主要输出
P1系统管理验证登录用户身份并按角色返回权限；提供密码修改入口。登录信息登录结果
P2部门与人员管理对部门与订阅人员信息进行录入、修改、删除，并分配账号与角色。部门与人员信息写入 D1、D2
P3报刊信息管理对报刊类别与报刊信息进行录入、修改、删除，支持模糊查询。报刊与类别信息写入 D3、D4
P4订阅管理接收订阅（或代订）申请，检索单价并计算金额，生成订阅单与明细，返回确认。订阅申请 / 代订申请订阅单与金额
P5查询统计按人员、报刊、部门维度查询订阅信息与统计汇总，支持模糊查询，结果可预览打印。查询统计请求查询统计结果
P6系统维护审核订阅单，管理操作日志，执行数据备份与恢复及参数设置。审核与维护指令审核结果与报告
P4.1接收订阅申请校验订阅人与报刊的有效性，形成有效订阅项。订阅申请有效订阅项
P4.2检索单价根据报刊编号从报刊表中检索单价。有效订阅项单价与订阅项
P4.3计算金额按 小计=单价×份数×订阅期数 计算每种报刊小计，并汇总总金额。单价与订阅项应收金额
P4.4生成订阅单生成订单编号，写入订阅单与订阅明细，记录操作日志，返回订阅单确认。应收金额订阅单确认 / 写 D5、D6
