5.1 数据库应用的硬件、软件环境介绍

硬件环境：开发与测试使用个人计算机一台（Intel Core i5 及以上处理器、16GB 内存、512GB 固态硬盘），数据库与应用系统部署于同一台机器，通过本机回环地址访问。

软件环境：操作系统 Windows 11；数据库管理系统 MySQL 8.0.40（InnoDB 存储引擎，字符集 utf8mb4）；应用开发语言 Python 3.13，Web 框架 Flask；数据库访问接口 PyMySQL；版本管理 Git。数据库脚本以 SQL 文件形式组织于 sql/ 目录，可使用 MySQL 命令行客户端或 Workbench 直接执行。

5.2 物理结构设计

对第四章得到的 7 个关系模式定义存储结构：所有表采用 InnoDB 引擎以支持事务与外键；字符集统一为 utf8mb4。类型选择上，标识类字段采用定长 CHAR（长度固定、便于校验），名称与描述类字段采用变长 VARCHAR 并按实际需求限制长度，金额采用 DECIMAL 以避免浮点误差，日期时间分别采用 DATE 与 DATETIME。各表字段设计如下（表5-1 ～ 表5-7）。

5.3 物理结构优化

5.3.1 索引设计

主码索引与唯一索引由主码、UNIQUE 约束自动创建；在此基础上，依据"最经常作为查询条件与分组统计依据的列建立索引"的原则建立普通索引，其中订阅单表建立（订单状态，订阅日期）复合索引以同时服务审核工作台过滤与时间段统计（利用最左前缀原则）。索引设计一览如表5-8 所示。索引并非越多越好：订阅明细表只建一个辅助索引，以降低高频写入时维护索引的开销。

5.3.2 函数设计

将订阅金额的计算口径统一封装为函数：小计金额 = 报刊单价 × 份数 × 订阅期数。函数内对报刊不存在的情况使用 SIGNAL 抛出明确异常。另设计按人员汇总累计订阅金额的函数供查询模块使用。

DELIMITER $$ -- 函数：计算订阅小计金额 CREATE FUNCTION fn_calc_subtotal(p_pub_id CHAR(8), p_qty INT, p_periods INT) RETURNS DECIMAL(10,2) READS SQL DATA BEGIN DECLARE v_price DECIMAL(6,2); SELECT unit_price INTO v_price FROM publication WHERE pub_id = p_pub_id; IF v_price IS NULL THEN SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = '报刊不存在，无法计算金额'; END IF; RETURN CAST(v_price * p_qty * p_periods AS DECIMAL(10,2)); END $$ -- 函数：某人累计订阅金额（仅已通过订单） CREATE FUNCTION fn_person_total_amount(p_sub_id CHAR(8)) RETURNS DECIMAL(12,2) READS SQL DATA BEGIN DECLARE v_total DECIMAL(12,2); SELECT IFNULL(SUM(det.subtotal), 0) INTO v_total FROM subscription o JOIN subscription_detail det ON det.order_id = o.order_id WHERE o.orderer_id = p_sub_id AND o.order_status = '已通过'; RETURN v_total; END $$ DELIMITER ;

5.3.3 存储过程设计

核心业务写操作统一封装为存储过程：①sp_place_order 创建订阅单（事务内锁定最近订单行取号，防止并发取号重复，并写入第一条明细）；②sp_add_detail 向待审核订单追加订阅明细；③sp_audit_order 审核订阅单（校验审核人必须为系统管理员，防止重复审核）；④sp_cancel_order 退订（校验仅本人、仅已通过订单）。业务规则校验失败时通过 SIGNAL 返回中文错误信息。

-- 过程：创建订阅单（详见 sql/04_procedures.sql，此处为核心逻辑） CREATE PROCEDURE sp_place_order( IN p_sub_id CHAR(8), IN p_start DATE, IN p_end DATE, IN p_pub_id CHAR(8), IN p_qty INT, IN p_periods INT) BEGIN DECLARE v_last INT; DECLARE v_order CHAR(10); DECLARE v_lock INT; DECLARE EXIT HANDLER FOR SQLEXCEPTION BEGIN ROLLBACK; SELECT RELEASE_LOCK('press_order_no'); RESIGNAL; END; IF NOT EXISTS (SELECT 1 FROM subscriber WHERE sub_id = p_sub_id) THEN SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = '订阅人员不存在'; END IF; -- 取号临界区以命名锁串行化：初版 SELECT … FOR UPDATE 在 10 线程 -- 并发下单压测中暴露间隙锁死锁（1213），改为 GET_LOCK 后消除死锁 SELECT GET_LOCK('press_order_no', 10) INTO v_lock; IF v_lock <> 1 THEN SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = '下单繁忙，请稍后重试'; END IF; START TRANSACTION; SELECT CAST(SUBSTRING(order_id,3) AS UNSIGNED) INTO v_last FROM subscription ORDER BY order_id DESC LIMIT 1; SET v_order = CONCAT('SO', LPAD(IFNULL(v_last,0)+1, 7, '0')); INSERT INTO subscription (order_id, sub_date, start_date, end_date, order_status, orderer_id) VALUES (v_order, CURDATE(), p_start, p_end, '待审核', p_sub_id); INSERT INTO subscription_detail (order_id, pub_id, quantity, periods) VALUES (v_order, p_pub_id, p_qty, p_periods); COMMIT; SELECT RELEASE_LOCK('press_order_no'); SELECT v_order AS order_id; END

5.3.4 触发器设计

触发器承担三类自动维护职责：金额一致性、订单状态机、操作日志。共设计 7 个触发器，如表5-9 所示。派生数据（小计、总金额）只能由触发器维护，应用侧直接写入将破坏一致性；状态机触发器保证订单只能沿"待审核→已通过/已驳回、已通过→已退订"路径迁移。

表5-9 触发器一览表
触发器名称表 / 时机职责
trg_det_before_inssubscription_detail / BEFORE INSERT按单价×份数×期数自动计算小计金额
trg_det_after_inssubscription_detail / AFTER INSERT将小计累加到订阅单总金额
trg_det_after_delsubscription_detail / AFTER DELETE删除明细后重算总金额
trg_ord_before_updsubscription / BEFORE UPDATE订单状态机校验；审核时自动填写审核时间
trg_ord_after_updsubscription / AFTER UPDATE状态变更自动写入操作日志

-- 触发器：插入明细前自动计算小计 CREATE TRIGGER trg_det_before_ins BEFORE INSERT ON subscription_detail FOR EACH ROW BEGIN DECLARE v_price DECIMAL(6,2); SELECT unit_price INTO v_price FROM publication WHERE pub_id = NEW.pub_id; IF v_price IS NULL THEN SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = '报刊不存在，无法订阅'; END IF; SET NEW.subtotal = CAST(v_price * NEW.quantity * NEW.periods AS DECIMAL(10,2)); END $$ -- 触发器：订单状态机校验 + 审核时间自动填写 CREATE TRIGGER trg_ord_before_upd BEFORE UPDATE ON subscription FOR EACH ROW BEGIN IF NOT (OLD.order_status <=> NEW.order_status) THEN IF NOT ( (OLD.order_status='待审核' AND NEW.order_status IN ('已通过','已驳回')) OR (OLD.order_status='已通过' AND NEW.order_status='已退订') ) THEN SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = '非法的订单状态变更'; END IF; END IF; IF OLD.order_status='待审核' AND NEW.order_status IN ('已通过','已驳回') AND NEW.audit_time IS NULL THEN SET NEW.audit_time = NOW(); END IF; END $$

5.3.5 事务设计

所有业务写过程内部均使用显式事务：START TRANSACTION 开启，全部成功后 COMMIT；任一语句异常由 DECLARE EXIT HANDLER FOR SQLEXCEPTION 捕获并 ROLLBACK，再由 RESIGNAL 将错误抛给应用。以"创建订阅单"为例，订单号分配、订单头写入、明细写入三步必须原子完成——若明细插入失败（如报刊不存在、份数越界），订单头一并回滚，杜绝"空订单"。并发控制方面，取号临界区以命名锁 GET_LOCK('press_order_no', 10) 串行化，避免两个并发请求取得相同订单号——初版采用 SELECT … FOR UPDATE 锁定最近订单行，性能测试（10 线程并发下单）中暴露间隙锁死锁（ERROR 1213），改为命名锁后死锁消除且取号保持严格唯一（详见 7.3.4 节）；订单汇总行的更新由 InnoDB 行锁天然串行化。

事务隔离级别采用 MySQL 默认的 REPEATABLE READ：审核、退订等校验-更新序列均在事务内先 FOR UPDATE 读取最新状态再更新，避免了幻读导致的重复审核。

5.3.6 权限控制设计

数据库角色与系统角色一一对应（r_sys_admin、r_dept_admin、r_sub_user），权限分配遵循最小特权原则：基础表的写权限仅授予系统管理员；部门管理员与订阅用户对业务表的写操作只能通过存储过程完成（EXECUTE 权限），从而保证业务规则校验不被绕过；订阅用户对人员表无任何权限、对报刊表只读，其"本人订单"通过视图 v_user_orders 按 CURRENT_USER 行级过滤。角色先集中授权，再授予应用账号，如表5-10 所示。

5.4 数据库实施

数据库实施按脚本顺序在 MySQL 8.0.40 中执行：①sql/01_create_database.sql 创建数据库 press_sub_db 及 7 张基本表（含全部约束与索引）；②sql/02_views.sql 创建 7 个视图；③sql/03_functions.sql、sql/04_procedures.sql、sql/05_triggers.sql 创建函数、存储过程与触发器；④sql/06_permissions.sql 创建角色与应用账号并授权。建库与建表的关键代码如下：

CREATE DATABASE press_sub_db DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci; USE press_sub_db; CREATE TABLE subscription ( order_id CHAR(10) NOT NULL COMMENT '订单编号（SO+7位流水）', sub_date DATE NOT NULL COMMENT '订阅日期', start_date DATE NOT NULL COMMENT '起订日期', end_date DATE NOT NULL COMMENT '截止日期', total_amount DECIMAL(10,2) NOT NULL DEFAULT 0 COMMENT '总金额（触发器汇总）', order_status VARCHAR(8) NOT NULL DEFAULT '待审核' COMMENT '订单状态', orderer_id CHAR(8) NOT NULL COMMENT '下单人（人员编号）', auditor_id CHAR(8) NULL COMMENT '审核人（人员编号）', audit_time DATETIME NULL COMMENT '审核时间', audit_comment VARCHAR(100) NULL COMMENT '审核意见', CONSTRAINT pk_subscription PRIMARY KEY (order_id), CONSTRAINT chk_ord_dates CHECK (end_date > start_date AND start_date >= sub_date), CONSTRAINT chk_ord_status CHECK (order_status IN ('待审核','已通过','已驳回','已退订')), INDEX idx_ord_orderer (orderer_id), INDEX idx_ord_status_date (order_status, sub_date), CONSTRAINT fk_ord_orderer FOREIGN KEY (orderer_id) REFERENCES subscriber (sub_id), CONSTRAINT fk_ord_auditor FOREIGN KEY (auditor_id) REFERENCES subscriber (sub_id) ) ENGINE=InnoDB COMMENT='订阅单表';
